# 2026-11-06

## 新建 Cloudflare Access 身份控制台 MVP（项目初始化）

从空仓库（仅 LICENSE/README）搭建完整 Worker 项目，实现「三种登录方式 + 登录后展示全量可获取个人信息」。

**需求澄清**：用户原话「上面所述的三种登录方式」但只写了 GitHub/Google。按 Access 架构解释为
One-time PIN（邮箱验证码）+ GitHub + Google 三个 Identity Provider；Access 是认证网关而非 IdP。

**固定配置**（用户提供）：
- Cloudflare Account ID: `9c2b9da6ca5beb3887a5f6152e3bac7d`
- 应用域名: `auth.hesen.dpdns.org`（wrangler custom_domain，自动建 DNS）
- Worker 名: `auth-identity-console`

**架构决策**：
- 认证完全交给 Cloudflare Access（Worker 不接触 client secret）；登录页由 CF 托管。
- 信息采集走四条互补通道：`ctx.access.getIdentity()`、jose 验签 `CF-Access-Jwt-Assertion`（JWKS + AUD + iss）、
  服务端代理 `/cdn-cgi/access/get-identity`、以及 headers + `request.cf`。页面递归渲染，不设字段白名单。
- 关键限制：Access 不透传 IdP access token，拿不到 GitHub/Google 原始 profile（avatar/login/locale）；
  JWT 的 `custom` claims 超 1KB 会被裁剪，完整 groups 必须走 get-identity。
- `workers_dev: false`：Access 应用按 hostname 建，留着 workers.dev 可绕过登录页。
- `auto_redirect_to_identity: false`：否则 Instant Auth 会跳过三选一登录页。
- jose 采用动态 import + JWKS 缓存，使离线预览脚本无需 node_modules 即可运行。

**交付文件**：`src/{index,identity,render}.js`、`scripts/{setup-access,render-preview}.mjs`、
`wrangler.jsonc`、`docs/SETUP.md`、`README.md`、`.dev.vars`（gitignore）、`public/preview.html`。

**验证**：`npm run check` / `npm run preview`（5 项冒烟全过）/ `npm run setup:dry`（请求体正确）/ 
`wrangler dev` 实测 HTTP 200、ctx.access dev 注入生效、四个数据源状态正确、未知路径 404。

**未完成（需用户凭证）**：未在云端真正创建 Worker / IdP / Access Application —— 缺 CF_API_TOKEN 与
GitHub/Google OAuth 凭证。用户补齐 `.dev.vars` 后执行 `npm run setup -- --write-config` 再 `npm run deploy`。

## 追加：排查 `npm run setup` 认证失败（10000 / 1010）

用户实跑 setup 报 `10000: Authentication error`。做对照实验（当前 token vs 明显无效 token）
逐端点实测，结论分两层，别混为一谈：

- **Token 本身有效**：`/accounts/:id`、`/zones`、`/access/identity_providers`、`/access/apps` 全 200；
  无效 token 对照组返回 `9106 / 9109 / 10000(401)`，形状完全不同。
- **`/access/organizations`（及 groups/bookmarks/certificates）403 + 10000**：权限不足，非凭证错误。
  官方文档要求 `Access: Organizations, Identity Providers, and Groups` 权限。
- **真正阻塞项**：`POST /access/identity_providers` → `403 {"code":1010,"error":"auth.forbidden"}`。
  换浏览器 User-Agent 结果不变（排除边缘指纹拦截），刻意 POST 空 body 也被同样拒绝
  （说明权限检查先于参数校验）→ **该 Token 只有读权限，没有 Edit/Write**。
- 注意 `/user/tokens/verify` 对该 Token 误报 `1000 Invalid API Token`，`/user/tokens` 报
  `9109 Valid user-level authentication not found`；**判断凭证是否有效要用 `/accounts/{id}`**，
  不能只看 verify 端点。Cloudflare 错误对象有时只有 `error` 字段没有 `message`。
