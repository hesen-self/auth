信息边界

信息边界：哪些拿得到，哪些拿不到

  • 能拿到：Access 归一化后的身份（email、name、idp、groups、devicePosture、ip、geo、device_sessions…）、JWT 标准与自定义 claims、以及 request.cf 里的地理/ASN/TLS 数据。本页已把这些字段全量递归展开，不做白名单过滤。
  • 拿不到：GitHub 的 login / avatar_url / bio / company、Google 的 picture / locale / hd 等 IdP 原始 profile。Access 只向应用交付归一化身份，不透传 IdP 的 access token，Worker 无法代用户调用 GitHub/Google API。
  • 头像来自 R2，不是 IdP：由于上面这条限制，本项目用 Cloudflare R2 保存用户自行上传的头像，按 user_uuid 命名，经 /api/avatar 读写；未上传时降级显示姓名首字母。要自动同步 IdP 头像，只能改用通用 OIDC + 自定义 claims，或在应用内另做 OAuth。
  • groups 有坑：写入 JWT 的 custom claims 超过约 1 KB 会被从尾部裁剪，groups 最容易丢；完整分组请走 /cdn-cgi/access/get-identity（本页通道 ③）。GitHub/Google 内置集成也不会自动带 groups，只有通用 OIDC/SAML IdP 支持显式配置 claims。
  • 想拿到原始 profile 的三条路：① 改用通用 OIDC 集成并配置自定义 claims / SCIM；② 应用内另行实现 GitHub/Google OAuth（自己保管 client secret 与 token，等于绕开 Access 的部分价值）；③ 让用户在前端自行授权后由浏览器直连 IdP API。MVP 阶段不建议，先把网关身份用好。
  • 安全约定：cookie、authorization、cf-access-jwt-assertion 等头已脱敏；JWT 验签失败会直接返回 403，不会把未验证的声明渲染出来。
